## 2026-10-26 · Brainstorm 与 Spec 初稿

**用户关键原话**

- 「我要用 Superpowers 模式让客服在一通会话里记得住前面聊过什么，把第一版的简单裁剪升级成正经的上下文管理。只管当前会话，不跨会话、不存用户画像。」
- 「三层结构……最近的留原文，一个字都不压；中间一层按规则截短……最远的异步压成一段段梗概。两个锚点划边界……降级只挪这两个 id、不搬数据。」
- 「摘要走后台异步……触发看用量不数条数，工具结果压根不落消息表，数条数看不见它涨。」
- 「梗概不许单独占一条 system，上游模板会把所有 system 上提合并渲染……前缀缓存整段作废。」
- 中途补 DDL 时：「两个文件都要 apply。」
- 面对两份旧稿冲突时：「以本会话需求+DDL为准。」
- 预算口径确认：「就按这组常数。」

**Claude 关键产出**

- 设计规格：`docs/superpowers/specs/2026-10-26-ch07-context-management-design.md`
- 预算反推并获确认：`history=5650`、`layer1=3954`、`layer2=1695`；常数为 system 2000 / evidence 5×300 / summary 650 / safety 10% / react_peak=(steps−1)×1200。
- 关键设计：锚点按「用户消息轮」对齐；层 2 当前调用按预算丢最老轮、摘要任务压全量层 2；摘要分段只追加，`conversations.summary` 只是最近 3 段投影。

**拒绝 / 纠偏**

- 拒绝把中途贴来的旧 Spec/Plan 直接当本章方案：它是两层滚动摘要、计数触发（30 条）、摘要单独 system、固定 3000 token，与本会话的三层/两锚点/按用量触发/禁 system 注入冲突。
- 指出旧文档的代码落点在本仓不存在：`app/core/memory.py`、`app/core/prompts.py`、`app/core/summarizer.py`、`app/db/repository.py`、`app/static/index.html`、`sql/ch07-ddl.sql`；实际是 `app/history.py`、`app/prompts/*.txt`、`app/db/repositories.py`（`ChatRepository` 类）、`app/static/chat.html`。
- 没有按旧稿的 `mewhelp` 库名和 `db_session_factory` fixture 硬写，先停下来确认。

**翻车与返工**

## 2026-10-26 · Spec builder check（独立评审）

**用户关键原话**

- 本轮无新用户输入；评审按流程自动派发。

**Claude 关键产出**

- 评审结论：7 个问题，全部属于「文档缺口/可由 builder 定」，无需再问用户；已回写 spec：
  1. 当前轮只出现一次：`slice_layers` 接收完整 State，层 1 拆成「当前轮之前 / 当前轮」，`turn-ctx` 插在当前用户之后，不重复追加。
  2. 降级每轮一次：新增 `prepare_context` 节点，写 State，`log_node` 持久化；`_agent_messages` 不写库。
  3. 补全 DDL 附录（两文件、类型/键/默认值），避免按猜测建模。
  4. 工具截断改到 `ToolMessage` 构造前：`query_faq` 先解析再截，JSON 结果用合法 JSON 包装；`ToolRegistry.execute` 不动。
  5. 侧栏排序改用 `MAX(messages.created_at)`，不再依赖 `updated_at`，避免摘要写库顶乱顺序。
  6. `RERANK_TOP_K` 明确为提示词证据预算，不改变检索/重排候选数；新增 `evidence_prompt`，全量 `evidence` 留给 EvidenceChecker。
  7. 摘要任务重读锚点：`summary_upto` 变了跳过，`layer1_from` 变小按新边界重算，为空/变大跳过。

**拒绝 / 纠偏**

- 没有把评审问题直接甩给用户：7 条都能从既有需求/DDL/本仓代码推出，按 builder call 处理并在 spec §18 标记。
- 拒绝在 `ToolRegistry.execute` 出口截断：会破坏 `_faq_evidence` 和 `refund_order_lookup` 的 JSON 解析。
- 拒绝用 `updated_at` 排侧栏：摘要任务后台写 `summary` 会触发 `onupdate`，把会话顶到前面。

**翻车与返工**

- 评审指出的当前轮重复拼接是 spec 初稿的真实缺陷，已改；未进代码，无返工。
- 评审指出的 DDL 缺失是 builder 看不到会话中途消息导致的误报——DDL 已在用户消息里，已原样补进 spec 附录 A。
