## 阶段 1：Brainstorm / 定稿 Spec

- **用户关键原话**
  - 总目标：「我要用 Superpowers 模式把客服系统升级成生产级架构:Workflow 确定性编排做骨架,主力 Agent 作为骨架里的核心节点。」
  - 热身：「先不用框架,手写一遍最裸的 Agent 循环(调 LLM,有工具调用就执行并把结果喂回去,没有就收敛出答案),看清它就是个带工具的循环,再用 LangGraph 重构。」
  - 骨架：「指代消解、意图识别、按意图分流、知识检索、置信度闸、主力 Agent、日志记录。」
  - 分流：「分流规则写死在代码里」；知识类强制检索、业务数据类直接进 Agent、投诉不进 Agent、闲聊固定话术。
  - 闸：「卡在知识类检索之后、进 Agent 之前,Agent 的答复是流式吐给用户的,答完再判就晚了。」
  - 处置：「转人工、建工单是两件事,分开做,都交用户在前端自选、不后端自动执行」；「点「转人工」前端直接展示「已转接人工客服」,再蹦一句「您好,我是客服小猫,请问有什么可以帮您的」」；「点「建工单」才调第 2 章的工单工具写 tickets 表」。
  - 工作要求：「全程走 Superpowers 流程」；「产出不是可单测代码的任务……把 TDD 那步换成拿标注样例或评估集跑一遍验证」；「过程留痕……不许收尾时一次性补记」；「涉及具体库、框架、API 的用法……一律先用 Context7 MCP 查最新官方文档」；「技术选型是定死的……发现矛盾或走不通,停下来问我」。
