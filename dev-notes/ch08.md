# CH08 开发过程记录：即插即用工具系统

> 按阶段追记，不做收尾一次性补记。每条记四样：用户关键原话、Claude 关键产出、拒绝/纠偏、翻车与返工。

## 2026-10-27 · Brainstorm / Spec 初稿

**用户关键原话**

- 「我要用 Superpowers 模式把客服系统的工具层从几个写死的内置工具，升级成即插即用的工具系统。」
- 功能需求 1–7：注册中心（名称/描述/JSON Schema 三件套，内置启动登记 + MCP 动态发现 + 不重启）、JSON Schema 校验回灌、只读/写权限门禁（唯一写操作 create_ticket，必须前端确认；MCP 声明不可信）、统一执行引擎（超时/重试/分诊/格式化）、tool_audit_logs 审计、两个自建业务 MCP Server（物流/售后）、建工单 interrupt + 前端预览卡（第 5 章按钮路径不动）。
- 技术栈定死：「MCP Server 用 MCP 官方 Python SDK 自建，走 Streamable HTTP 传输」「MCP Client 用 LangChain 官方 langchain-mcp-adapters 的 MultiServerMCPClient 多 Server 接入」。
- 本章不做：Skill 机制、仓储等更多外部系统。
- 验收 1–6：新工具只注册可用；两个 MCP Server 查到数据；MCP 加工具只重启该 Server；建单确认落库带工单号；取消落权限拒绝审计；读超时重试/写超时不重试。
- 工作要求：「全程走 Superpowers 流程，技能自动触发」「纯 Prompt/数据类任务用标注样例或评估集替代 TDD」「工单预览卡片前端用 Vibe Coding」「dev-notes/ch08.md 按阶段追记」「库/Framework 用法先查 Context7」「技术选型定死，走不通停下来问」。
- 中途补 DDL：`tool_audit_logs` 建表语句，明确不挂外键、中文 ENUM、utf8mb4、写审计不能被引用约束拦住。

**Claude 关键产出**

- 现状摸底：`build_tools()` 写死 5 个工具；`ToolRegistry` 无 Schema 校验/权限/审计；`agent_tools` 直接拦截 create_ticket 成前端按钮；第 6 章订单选择器是 `pending` 槽位 + `next` 消息续跑，不是 interrupt；checkpointer 为 `AsyncSqliteSaver`，`thread_id=conversation_id`。
- Context7 核对：MCP Python SDK v2 用 `mcp.server.mcpserver.MCPServer` + `run(transport="streamable-http", host, port)`；`langchain-mcp-adapters` 用 `{"transport":"streamable_http","url":...}` + `get_tools()`（每次调用新建会话）；LangGraph 1.2.16 `StateSnapshot.interrupts`、`Command(resume=...)`。
- Spec 初稿：`docs/superpowers/specs/2026-10-27-ch08-tool-system-design.md`。
- 关键设计：插件目录热加载；MCP 每轮发现 + 单 Server 缓存；写操作独立图节点 `ticket_confirm` 避免 resume 重跑读工具；`permission_required` 不落审计、确认/取消时只落一条；审计独立会话、失败不阻塞；工单号兜底追加。

**拒绝 / 纠偏**

- 拒绝把第 6 章「订单选择器」当成现成 interrupt：它实际是 pending 槽位 + 前端下一条消息，本章要真正引入 `interrupt()` / `Command(resume=...)`。
- 拒绝用 MCP tool annotations / Server 描述判断只读：权限只按本侧 `MCP_READ_ONLY_SERVERS` / `MCP_WRITE_TOOLS` 配置。
- 拒绝把写操作确认放在 `agent_tools` 同节点里：resume 会让节点从头重跑，导致同轮读工具重复执行/重复审计；改为独立 `ticket_confirm` 节点。

**翻车与返工**

- 无代码返工（尚未进入实现）。
- 待办：builder check、用户批准 spec、写实现计划。

## 2026-10-27 · Builder Check（spec 评审）

**用户关键原话**

- 本阶段无新增用户输入；评审按流程自动派发。

**Claude 关键产出**

- 独立 builder 读完 spec + 代码，提了 5 个问题，按重要性排序：
  1. **售后/建单意图到不了 `agent_llm`**：`INTENT_TO_ROUTE` 把售后送退款子流程、其他送固定澄清；「订单1001还在保吗」「帮我建个工单」都不会走 Agent；多轮补描述还会被重新分类离开 Agent。需要改路由或加草稿槽。
  2. `tool_audit_logs` 完整 DDL 不在 spec 里（builder 看不到会话中途消息）。
  3. `/api/agent`（`run_turn`）遇到 ticket interrupt 怎么处理？否则会把 checkpoint 留在 pending，后续聊天全被拦。
  4. 超时竞态：`TOOL_TIMEOUT_SECONDS` 和 `MCP_REQUEST_TIMEOUT_SECONDS` 都是 5，6 秒延迟可能先被 HTTP 超时捕获，审计状态不稳定。
  5. `McpToolProvider` 缓存与 `ToolAuditWriter` 的生命周期：每轮新建 `build_deps` 会让缓存失效；全局又难测试。
- 处理结果：
  - 第 1 条列为「必须问用户」，见下。
  - 第 2 条是 builder 看不到会话中途消息导致的误报；已把用户原文 DDL 作为附录 A 补进 spec。
  - 第 3 条按 builder call 处理：`run_turn` 检查 `snapshot.interrupts`，`AgentResponse` 加 `pending_confirm`，不落 assistant 消息。
  - 第 4 条按 builder call 处理：MCP HTTP 超时默认 10 > 引擎 5，超时统一归 `timeout`，读重试/写不重试。
  - 第 5 条按 builder call 处理：`McpToolProvider`、`ToolAuditWriter` 都提升为 `Runtime` 级单例，注入 `build_deps`。

**拒绝 / 纠偏**

- 没有把 5 条都甩给用户：4 条能由既有约束和代码推出，直接改进 spec。
- 拒绝让 builder 自己编 DDL：用户已给原文，按原文落 `sql/ch08-ddl.sql`。
- 拒绝把 MCP 超时调得比引擎低：那会让 6 秒延迟的验收结果依赖竞态，审计状态不可复现。

**翻车与返工**

- 初稿确实假设了「售后/建单能到 Agent」而没核对 `routing.py`，是 spec 的真实缺口；已在 §11.0 标为待用户拍板，未进实现，无代码返工。
- 待办：用户选路由方案 A/B/C → 更新 spec §11.0 → 用户批准 spec。

## 2026-10-27 · 路由方案拍板

**用户关键原话**

- 选择：「前置分流+草稿槽 (Recommended)」——「在意图分类前加一个确定性 gate:正则识别『明确要求建工单』和『查在保/退货进度』直达 Agent;ticket_draft 草稿槽跨轮保留,让补充的描述也能到 Agent。第 6 章八类意图与确定性节点不动。」

**Claude 关键产出**

  - 强制路由记录 `intent="建单"/"售后查询"`、`intent_confidence=1.0`、`intent_tier="rule"`，不调用意图模型。
- spec 附录 A 补入用户原文 DDL；§16 增补 13–16 条 builder calls；§14 增补路由测试项。
- 文件清单补充 `app/runtime.py`、`app/graph/routing.py`、`tests/test_agent_api.py`、`tests/test_chat_service.py`。

**拒绝 / 纠偏**

- 没有采用方案 B（新增两类意图）：多轮补描述仍要草稿槽，且要改第 6 章评估集；方案 A 的「明确要求建单」本来就是确定性话术，正则更稳。
- 没有采用方案 C（售后/其他整体走 Agent）：会破坏第 6 章退款子流程与其他澄清行为。

**翻车与返工**

## 2026-10-27 · 实施计划初稿与自检

**用户关键原话**

- 「批准，按这版设计进计划」

**Claude 关键产出**

- 实施计划：`docs/superpowers/plans/2026-10-27-ch08-tool-system.md`。
- 10 个任务：依赖/DDL/模型 → 注册中心/插件 → 校验/权限/格式化 → 重试/分诊/审计 → 内置目录/工单落库/下线物流 → MCP 客户端/Runtime 单例/async build_deps → 两个 MCP Server → 路由 gate/interrupt/API/Prompt/评估 → 前端预览卡（Vibe Coding） → 验收/评审/收尾。
- 自检补的缺口：
  - 加 `ch08-tool-system` 分支创建步骤；
  - `build_core_specs`/`build_builtin_specs` 增加 `ticket_create_delay_seconds` 参数，供验收 6 写超时注入；
  - `build_runtime` 启动时 `ensure_plugins_loaded`，满足「内置工具服务启动时登记」；
  - `refund_order_lookup` 直调 `query_order` 传合成 `tool_call_id`，保证审计可对回；
  - 非 `create_ticket` 的插件写工具走 `registry.reject`，不进入无 UI 的确认流；
  - `_graph_input` 每轮重置 ticket 字段但不重置 `ticket_draft`；
  - `/api/agent` 开始前也检查 pending，避免新输入污染 checkpoint；
  - 前端 `loadHistory` 保留带 `pendingConfirm` 的空文本项。
  - 明确 `MCP_REQUEST_TIMEOUT_SECONDS=10` > `TOOL_TIMEOUT_SECONDS=5`，避免第 6 章验收 6 的超时竞态。

**拒绝 / 纠偏**

- 没有把计划写成代码全文：以签名、测试断言、验证命令为主。
- 拒绝使用 SDK 私有 tool manager 做注册断言：工具注册以真实 MCP 进程冒烟为准。

**翻车与返工**

- 初稿漏了「非 create_ticket 写工具」的兜底和 `refund_order_lookup` 的审计 id，已在计划内补齐；尚未进代码，无返工。

## 2026-10-27 · 计划独立评审 / 修正

**用户关键原话**

- 本阶段无新增用户输入；评审按流程自动派发。

**Claude 关键产出**

- 独立评审提了 8 条，逐条处理：
  1. MCP SDK 实际解析到 `mcp==1.30.0`（适配器约束），spec/plan 原写 v2 `MCPServer` → 改用官方 `mcp.server.fastmcp.FastMCP`，传输仍是 Streamable HTTP；不换库。
  2. `ToolAuditLog` 让 `tests/test_db_models.py` 的表清单断言变红 → Task 1 已同步，452 用例全绿。
  3. 删除 `build_tools` 会 orphan `scripts/bare_agent_loop.py`、`evals/run_tool_routing_eval.py`、`tests/test_bare_agent_loop.py` → Task 5 增加三处迁移。
  4. Task 7 的工具/测试同步/异步不一致 → 统一为 `async def` + `await asyncio.sleep`，测试也 async。
  5. `refund_order_lookup` 传 `tool_call_id` 会打到 `test_refund_subflow.py` 的旧 FakeRegistry → Task 8 增加该测试文件适配。
  6. `ToolResult.meta` 契约不一致 → 定为：成功 `{"payload": <格式化 dict>}`，`permission_required` `{"arguments": <原始参数>}`；`ticket_no` 从 `meta.payload` 取；spec §7.2/§11.2 已同步。
  7. 只给 create_ticket 传 `tool_call_id` 会让其他工具审计缺 id → Task 8 改为所有工具统一传 `call_id`。
  8. MCP 配置没接进 `build_runtime` → Task 6 明确 `enabled=settings.mcp_enabled`、每个 connection `timeout=settings.mcp_request_timeout_seconds`。

**拒绝 / 纠偏**

- 没有为了用 v2 而强行 pin `mcp>=2.3`：`langchain-mcp-adapters 0.3.2` 把 mcp 约束在 1.x，强行 pin 会破坏官方适配器；用同版本官方 SDK 的 FastMCP，技术选型不变。
- 没有保留「meta 里塞 preview」的写法：执行引擎不知道工单预览结构，改为返回原始参数，由 `agent_tools` 构造预览；职责更清楚。

**翻车与返工**
